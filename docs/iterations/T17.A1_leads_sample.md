## Método de sampling

- Dataset: `zifeng-ai/LEADSInstruct`, config `study_search_publication`, split `test` (4217 records).
- Sampling: `numpy.random.default_rng(seed=42).choice(4217, size=3, replace=False)`.
- numpy 2.4.2, datasets 4.8.5.
- Script ejecutado: `scripts/select_leads_sample.py --n 3 --seed 42`.
- Modo de carga: `load_dataset(..., streaming=True)` y materialización a lista
  Python. Se usa streaming porque el cargador no-streaming falla al generar el
  split `prospective_test` por desajuste de esquema upstream
  (`origin.pico` viene tipado como string en ese split, no como struct). El
  split `test` sí se genera correctamente y caben sus 4217 records en memoria.
- Índices ordenados ascendentemente para legibilidad reproducible: `[376, 2760, 3262]`.

## Justificación de N=3

Smoke-first obligatorio por §9 del pre-registro (`docs/iterations/T17.A1_hypothesis.md`):
validar la mecánica del pipeline antes de escalar. La decisión de escalar a
N=15-20 (§5.2) requiere análisis explícito de los resultados del smoke y
nuevo prompt de aprobación al usuario; este artefacto no autoriza por sí
mismo el full run.

# T17.A1 — Sample N=20 (Fase D.1, stitched)

**Fecha**: 2026-05-19T12:51:11Z
**Artefacto**: `data/groundtruth/leads_full20.json` (gitignored, force-added).
**Parent smoke**: `data/groundtruth/leads_smoke.json` (sin cambios).

## Motivación del método "stitched"

La sanity gate del plan exige que `samples[0..2]` del N=20 sean bit-idénticos
a los 3 records del smoke (MLSEP017395 / MLSEP019779 / MLSEP020281). Esa
invariante **no es satisfacible** reproduciendo el método del smoke con
`--n 20`: `numpy.random.default_rng(seed).choice(N, size=k, replace=False)`
genera una permutación parcial dependiente de `size`, por lo que el k=3 no es
subconjunto del k=20. Diagnóstico completo en
`outputs/eval/T17.A1/D1_resolution_log.md`.

El usuario autorizó el desbloqueo mediante muestreo **stitched**:

1. Posiciones 0..2: los 3 índices del smoke en orden de smoke (no
   re-ordenados): `[376, 2760, 3262]` -> `MLSEP017395`, `MLSEP019779`,
   `MLSEP020281`.
2. Posiciones 3..19: 17 índices nuevos extraídos del complemento
   `sorted(set(range(4217)) - {376, 2760, 3262})` (4214 candidatos) con
   `numpy.random.default_rng(42).choice(len(remaining), size=17, replace=False)`,
   mapeados de vuelta al espacio de índices del split, y ordenados
   ascendentemente.
3. Final `selected_indices` = `[376, 2760, 3262]` + delta ordenado
   ascendentemente.

## Schema de `metadata` añadido

- `sampling_method`:
  `"smoke3_prefix + numpy.random.default_rng(42).choice(remaining_indices_after_smoke, size=17, replace=False)"`.
- `pairing_strategy`: `"stitched: smoke N=3 hard-prefixed, 17 new samples drawn from complement with seed=42"`.
- `parent_smoke_file`: `"data/groundtruth/leads_smoke.json"`.
- `smoke_prefix_indices`, `smoke_prefix_ids`, `delta_indices_sorted`:
  informativos para reproducibilidad y auditoría.

El resto del schema es idéntico al smoke (`dataset`, `config`, `split`,
`split_size=4217`, `seed=42`, `n=20`, `numpy_version`, `datasets_version`,
`timestamp`, `git_commit`).

## Script utilizado

`scripts/select_leads_sample.py` extendido con la flag opcional
`--stitch-from-smoke PATH`. La ruta de smoke (sin la flag) preserva el
comportamiento original bit-a-bit. Comando ejecutado:

```bash
~/meta-analisis-automatizado/venv/bin/python \
  scripts/select_leads_sample.py --n 20 --seed 42 \
  --stitch-from-smoke data/groundtruth/leads_smoke.json \
  --output data/groundtruth/leads_full20.json
```

El script incluye una sanity gate interna que aborta con código 3 y sin
escribir el artefacto si `samples[0..2].id` no coincide con `smoke_prefix_ids`.
En esta ejecución la gate pasó.
