## Principios de diseño

**Cambio de modelo, no de arquitectura.** Los 9 agentes del pipeline conservan sus responsabilidades, su orden y sus contratos I/O. La única variable nueva es el modelo que ejecuta cada paso.

**Backend dispatcher con default Claude.** El orquestador acepta `--backend claude|qwen` con default `claude`. El default cubre el caso de uso real (replicación 100% Claude). El flag existe para diagnóstico, escape hatch en defensa, y permite mini-ablaciones ad-hoc por agente si tras el run principal hay tokens disponibles.

**Checkpoints granulares.** Para los agentes que procesan N papers (A3, A4, A5, A6) el checkpoint es paper-por-paper. Para el resto (A1, A2, A7, A8, A9) checkpoint a nivel agente completo. Una sesión que se corta se reanuda con `--resume <run_id>` sin re-quemar tokens.

**Contrato I/O por archivos.** Cada agente lee del filesystem lo que produjo el anterior y escribe a un path determinista. No hay paso de contexto en memoria entre agentes. Esto es lo que hace la migración trivial: el contrato es el archivo, no la implementación.

**Zonas sagradas heredadas.** `app.py`, `config.yaml`, `.env`, `data/gold_standard.json`, `venv/`, `.git/`, y los módulos Qwen `agents/agentN_*.py`. Bloque C es aditivo.

Mínimo principio: cada subagente solo declara las herramientas que necesita.

- **sam_a1_protocol**: Read (config), Write (su output). Sin Bash, sin Web.
- **sam_a2_search**: Read, Write, WebFetch (APIs científicas) o Bash (curl/python a APIs). Validar qué necesita el módulo Qwen actual.
- **sam_a3_screening**: Read, Write. Sin Bash.
- **sam_a4_fulltext**: Read (PDFs extraídos a texto previo), Write. Sin Bash.
- **sam_a5_extraction**: Read, Write.
- **sam_a6_quality**: Read, Write.
- **sam_a7_synthesis**: Read, Write, Bash (Rscript meta_analysis.R).
- **sam_a8_manuscript**: Read, Write.
- **sam_a9_explainer**: Read, Write, Bash (pandas → xlsx).

## Orquestador

Archivo: `orchestrator.py` en raíz del repo.

Comportamiento:

1. **Inicio nuevo run**: genera `run_id`, crea `outputs/<run_id>/manifest.json` con todos los agentes en `pending`, ejecuta agentes en orden A1→A9.

2. **Resume**: `--resume <run_id>` lee manifest, identifica primer agente no completado, retoma. Para agentes con checkpoint paper-por-paper, lista `<agent>/_index.json` y procesa solo los pendientes.

3. **Backend dispatch**: para cada agente consulta `config.backend_default` y `config.backend_overrides[agent_id]`. Si backend es `claude`, invoca el subagente CC vía Task tool. Si es `qwen`, invoca el módulo `agents/agentN_*.py` correspondiente.

4. **Persistencia incremental**: tras procesar cada paper en A3/A4/A5/A6, escribe el `<paper_id>.json` y actualiza `_index.json` Y manifest. Si la sesión muere, el siguiente resume sabe exactamente dónde quedó.

5. **CLI**:
```
python orchestrator.py --query "..." [--subset partition.json:dev] [--backend claude|qwen]
python orchestrator.py --resume <run_id>
python orchestrator.py --resume <run_id> --start-at sam_a5_extraction  # forzar restart desde un agente
python orchestrator.py --resume <run_id> --backend-override sam_a4_fulltext=qwen  # mini-ablación
```

## Backend dispatcher

Función `dispatch(agent_id, backend, input_paths, output_dir) -> AgentResult`.

- Si `backend == "claude"`: invoca subagente CC con prompt parametrizado por `agent_id`, espera respuesta, parsea JSON, valida contra schema, escribe a `output_dir`.
- Si `backend == "qwen"`: importa el módulo `agents.agentN_*` correspondiente, llama su entrypoint con los paths, obtiene resultado.

Validación post-dispatch: schema check. Si falla, marca agente `failed` en manifest y aborta. El run se puede reanudar tras fix.

## Variabilidad y reproducibilidad

Claude no expone seed determinista. Mitigación: temperature mínima soportada (probablemente 0 o el equivalente), y `n_runs=3` para agentes evaluables (A3, A4, A5, A6) reportando mean ± std o IC95%. Para A1, A2, A7, A8, A9 un run y reportar como informativo.
